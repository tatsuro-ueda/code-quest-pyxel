# UX Policy

子どもが「いま何が起きているか」を迷わず受け取れ、親が補助するときも主体性を奪わないための UI / 表記 / 操作方針。

## 1. 子どもが読める表記を優先する

- せりふ、メニュー、エラー文言はひらがな中心で書く
- 漢字を使うときは、文脈だけで意味が取れるかを先に確認する
- 子ども向け表示で英語や内部用語をそのまま出さない

## 2. いま選んでいる操作だけを見せる

- 画面上で競合する案内を同時に重ねない
- 前の操作結果メッセージが次の選択 UI を隠さないようにする
- 会話 UI では現在ページだけを表示し、前ページが残らないようにする
- ガイドは次の一歩を示すが、答えを全部は表示しない
- 最奥の目印キャラのような「次に踏む場所が見て分かる」手がかりは、口頭説明の代わりになる child-facing UX として扱う

## 3. 押した実感を返す

- ボタンや選択肢は、押した直後に変化が分かる見た目か音を返す
- 画面遷移は CJ44 の方針に従い、複雑なフェードより即時で分かる切替を優先する
- 進行不能やエラー時は、子どもが次に何をすればよいかを短く返す

## 4. 危険操作は無言で通さない

- 保存上書き、データ削除、子どもの変更を失う操作には確認を入れる
- 子どもの編集面である Code Maker を内部都合で脇役化しない
- AI 側の都合で `.pyxres` や、Code Maker で作った効果音・音楽・画像など子どもの編集内容を勝手に置き換えない
- Code Maker import UI は **zip 内の code は採用せず、絵・音・タイルマップなど resource だけを戻す** ことが、親の口頭補足なしでも子どもに誤解されない形で見えるようにする

## 5. Web 共有は見せやすさを優先する

- URL を開いたらすぐ遊べることを優先する
- スマホで全画面プレイできる導線を保つ
- 共有導線を壊す変更は、公開 URL 相当の実物確認まで done にしない
- selector page で `あそんでみる` を dead link にしない（wrapper artifact 欠損も UX 破綻として扱う）
- preview source が無いときは、古い card を見せるより card 自体を出さないほうが子どもに正直である

## 6. 親は補助者であり、決定者ではない

- フィードバックをどう反映するかの最終判断は子どもが持つ
- 親向けの補助 UI やログは、子どもの体験を邪魔しない位置づけにする
- 子どもが「自分たちのゲーム」と言える流れを崩さない

## 7. 小さな迷いを溜めない（具体事例）

積み重なる小さな迷いは大きな離脱になる。次のような具体改善は、それ自体は小さくても child-facing 体験の底上げにあたる：

- **宿屋のコストを先に見せる**：「とまる？」の前に金額が見えていれば、選択直前に頭を使い直さなくて済む
- **所持マークは短い読める表記にする**：店の `所持` バッジが clipping して読めないと、買って良いか判断できなくなる
- **HP/MP 満タンの宿屋利用はスキップする**：効果のない宿泊で gold だけ減ると、子どもの「押してよかった」が崩れる
- **status bar の zone 名表示で未定義エラーを出さない**：Code Maker 版の表示崩れは、子どもが最初に見る場面の信頼を傷つける
