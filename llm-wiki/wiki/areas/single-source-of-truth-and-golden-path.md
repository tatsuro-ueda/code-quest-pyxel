# Single Source Of Truth And Golden Path

## 核心

`framework-rule` は、AI が壊しやすい場所を「正本を一つにする」と「本番の通り道を通す」で先に封じる。データの正しい置き場と、実際のユーザー導線を固定しておけば、見かけだけの green を減らせる。

## SSoT

- 同じ意味のデータを複数箇所に持たない
- 生データ直読みや都合のよい参照先切り替えをしない
- ユーザー編集より自動生成を優先しない
- `src/` と `assets/` を正本にし、 `dist/` を source 扱いしない
- `assets/*.yaml -> tools/gen_data.py -> src/generated/*.py -> src/game_data.py` の一方向生成を守り、手動多重更新より regenerate を優先する
- dialogue も `assets/dialogue.yaml -> tools/gen_data.py -> src/generated/dialogue.py -> src/game_data.py` の一方向へ寄せ、`src/dialogue_data.py` は互換レイヤーにとどめる
- `.pyxres` の truth は runtime self-heal に置かず、Code Maker 側の実体と build / verify 側の検査で守る

## Golden Path

- unit test green だけで終わらない
- 起動、メニュー、戦闘、配布物など本番導線を最低 1 回は通す
- bundle や実物確認を後回しにしない
- Code Maker zip、公開 URL、play log のような user-facing artifact も通り道に含める
- Code Maker 向け zip では、zip 内 `main.py` と `my_resource.pyxres` が現行正本と一致し、展開物が headless 起動することまで確かめる
- build gate では構文 green だけでなく、headless 起動で `Game()` 初期化と 1 フレーム描画が通ることを最低条件にする

## この repo への含意

- docs、pyxres、配布物、save payload のどれが正本かを先に固定する
- 「直した」ではなく「ユーザーが触る通り道で動いた」ことを done とみなす
- generated data や packaging artifact も、`正本から再現できるか` で点検する
- resource mismatch を startup self-repair に任せず、verify で止める方が current truth と相性が良い
- `main.py` が single-file 同期を持つなら、SSoT 移行は generated file だけでなく sync script まで含めて完了扱いにする
- いま読んでいる resource と配る resource が一致することは、`.pyxres` の中身だけでなく `どの source を正本に選ぶか` の SSoT 問題である。
- imported SFX slot が埋まっているなら、その slot を truth として扱い fixed definition で上書きしないのが golden path に合う。
- runtime modularization や single distribution は、repo 構造だけでなく build / Code Maker artifact まで通して初めて done になる。
- 可読性改善でも `src/generated/` を触らないこと、town refactor でも grep と pytest で user-facing path を通すことが SSoT / golden path の具体例である。
- guardrails PRD 同期は、rule の正本を `framework-rule.md` と `customer-journeys.md` に戻し、PRD を追従させる SSoT 作業だった。
- play session schema 拡張でも migration と report の両方を通す必要があり、observability も DB / server / report をまたぐ golden path で扱うべきだと分かる。
- PlayerModel residue crash と stale `M.SHOPS` 参照は、new truth へ移行した後に旧 field/shape を残すことが SSoT break になる典型例だった。
- 新しい crash harness を足す前に既存 `test_cjg_*` coverage を確認した判断は、`何が done 済みか` の正本をテスト実態へ戻す作業でもあった。
- world map の truth を pyxres に戻し、ExploreModel を imagebank/tilemap 直読へ寄せた変更は、この repo の地形 SSoT を resource 実体側へさらに押し戻した。

- world_map/dungeon_map cleanup plans, test rewrite, and water2 rebake work pushed map truth back to tilemap/imagebank/pyxres and away from runtime snapshots.
- BGM pyxres SSoT, bundle rebuild, and build runbook extended the same truth-first rule to audio and release artifacts.
- dist rename and docs sync reduced stale names and stale entrypoints that make golden paths lie.
- architecture_rules YAML/tree-first/checker work turned repo facts themselves into a new SSoT that both humans and AI can query.
