# Customer Jobs Summary

## TL;DR

この source は、Block Quest Pyxel の顧客ジョブを子ども、親、友達の三者で整理した基礎文書です。中心論点は「単発の機能」ではなく、子どもが `遊ぶ -> 作る -> 自分で判断する -> 共有する` と進む連続体験を壊さないこと、そして親が主役化せずにその進歩を支えることにあります。

## 主要ジョブ

- 子どもは `没入` `表現` `自己判断` `共有` の各面で、自分の感覚と連続性を失わずに進みたい
- 親は `関係` `成長支援` `主体性支援` `手応え` `理解` の各面で、支えたいが奪いたくない
- 友達は `気軽にその場で体験できること` を求める
- 特に `JIS_PARENT_AUTONOMY` は、決定権を子に残し、実装や配信の手数を親が引き受けるという役割分担を明示する

## 競合理解

- Scratch は触りやすいが、完成度、即時共有、深い比較判断の面で止まりやすい
- Roblox は没入や社会性に強いが、自作や主体性の連続性を保ちにくい
- RPG Maker は作品化しやすいが、親や作り手の主導が強くなりやすい
- vibe coding は速いが、子どもの `自分で作った感` や `自分で決めた感` を失わせやすい
- 教育系 SaaS は可視化に強いが、理解が監視へ傾きやすい

## 深い洞察

- 競合はそれぞれ単一のジョブ最適化に寄りやすく、`連続した体験` を壊す
- この product の差分は、子どもの人格的な遷移 `遊ぶ -> 作る -> 判断する -> 共有する` を一本の流れとして守る点にある
- 親の価値は `教える人` や `管理する人` ではなく、子どもの意志を消さずに前進を成立させる支援者である
