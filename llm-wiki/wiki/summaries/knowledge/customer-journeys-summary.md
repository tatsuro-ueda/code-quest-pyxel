# Customer Journeys Summary

## TL;DR

この source は、Block Quest Pyxel の顧客ジョブを実際の体験ループへ落とした journey 集です。要点は、`開発` `デバッグ` `演出` `共有` `発展` `承認` `ガードレール` の各ループを切らさず、外部依存の Buy と自前実装の Make を組み合わせて、親子の好循環を回すことにあります。

## 主要トピック

- ソリューションは `Buy` 4 つと `Make` 3 つで構成される
- `Make1 承認キュー` `Make2 Code Maker反映パイプライン` `Make3 ガードレール` が自前価値の核
- journey は `開発` `デバッグ` `演出` `共有` `発展` `承認` `ガードレール` の 7 群に分かれる
- `承認ループ` は子どもの主体性を仕組みで守る
- `ガードレール` は壊れた AI 出力を子どもへ届けないための前提条件

## 競合理解

- Scratch / Roblox / RPG Maker / vibe coding の弱点を、各 journey の Before で具体的に可視化する
- 競合比較は abstract な表ではなく、「この体験でどこが止まるか」を CJ 単位で示す

## 深い洞察

- 価値は個別機能でなく、複数のループが閉じ続けることにある
- `承認キュー` と `ガードレール` は単なる内部実装でなく、主体性と安心のための product 機構である
- `共有` と `実公開ログ` は親子の内側のループを、友達を含む外側のループへ広げる
