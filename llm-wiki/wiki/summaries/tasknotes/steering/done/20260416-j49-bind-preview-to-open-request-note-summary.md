# 2026年4月16日 J49 次の依頼が来たら前の preview を current に繰り上げる Summary Draft

## summary

この tasknote は、preview を open request note に結びつける案から出発しつつ、最終的には「次の更新が来たら前のおためしばんが本番になる」という昇格ルールまで視野を広げた記録です。焦点は、`request note が一致するか` だけでは preview/current の運用を説明しきれず、前の preview を source レベルで current に回す仕組みが要ると分かったことでした。

## key_points

- 出発点では、preview を現在の open preview note へ結びつける案が最小に見えた。
- その案だけでは、前の preview を current に回す運用まで扱えなかった。
- user から「次の更新が来たら前のおためしばんが本番になる」という追加ルールが入った。
- その結果、`request note 一致` だけでは不十分だと分かった。
- preview/current の関係を、request-note anchor から promotion flow へ寄せ直す必要が見えた。
- この note は、preview の意味づけを実運用ルールへ接続する橋渡し役になった。
